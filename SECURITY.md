# Безопасность и приватность

Модель угроз: ошибочная публикация локальных данных; credential в staged snapshot или промежуточном коммите; опасная shell-команда; неполный результат, объявленный успешным; недоверенные входные файлы. Guard — дополнительная эвристика, не security boundary и не полноценный shell parser. Обфускация, сборка строки по частям, вложенные интерпретаторы и неизвестные форматы ключей могут пройти. Сохраняйте permissions и sandbox хоста.

## Слои защиты

1. PreToolUse: malformed/oversized input прекращает guard с exit 2; секреты в stderr не печатаются.
2. pre-commit: проверяет **staged** bytes, приватные пути и карточки из отдельного snapshot, а не unstaged рабочую копию. Локальный hook можно обойти; он не заменяет CI.
3. Sync: точный manifest, свои lock и проверка Git lock, только ожидаемая ветка, сохранение чужого index, checked outcomes, fast-forward-only, сканирование outgoing commit trees. Сетевой сбой возвращает failure. Очередной запуск не должен автоматически удалять stale locks.
4. CI: отдельный Gitleaks, полный fetch history, pinned SHA Actions и read-only permissions. Защита main настраивается владельцем GitHub; YAML её не включает.

При findings выводятся путь и тип, а не значение. Gitleaks запускается с `--redact=100`. Синтетические секреты в тестах собираются из частей. При настоящей утечке отзовите ключ у провайдера; простое удаление файла из последнего коммита не убирает историю.

## Экспорт

По умолчанию выключен. Вход допускается только внутри `ORCHESTRATOR_TRANSCRIPT_ROOT`; выход — `VAULT_ROOT/_session_exports`. Режим redacted скрывает известные credential patterns; **имена, переписка, коммерческие сведения и неизвестные ключи могут сохраниться**. Режим full сохраняет исходное содержимое. Согласие на локальный экспорт не является согласием на публикацию или синхронизацию vault.

Выберите срок хранения и правила доступа владельцем данных. Встроенного retention scheduler, шифрования и удаления резервных копий нет. Источник не удаляется. Копирование рабочих деревьев через robocopy /MIR больше не выполняется. Export/sync не устанавливаются как Stop hooks.

## Дополнительные компоненты

`repo-inventory --external-tools` может скачать npx-пакеты и исполнить конфигурацию анализируемого проекта; используйте на доверенной копии. Silero загружает Python pickle из доверенной модели. Медиа-рецепты, старый entry-file guard и site-build нуждаются в отдельной проверке среды. Не используйте их наличие в репозитории как подтверждение безопасности.

## Сообщение об уязвимости

Не публикуйте активный ключ или полный транскрипт в issue. Сначала отзовите credential, подготовьте минимальное воспроизведение на синтетических данных и согласуйте с владельцем приватный канал. Не заявляем наличие GitHub private vulnerability reporting, пока оно не проверено.
