# /reviu

Полное ревью проекта по двухслойной схеме: инструменты проходят каждую
строчку, модель читает срез и идёт вглубь только по адресам из него.

**Регламент целиком** (если ведёшь свой файл методики ревью в vault — читать при
первом запуске в сессии, дальше не перечитывать). Шаги ниже самодостаточны.

## Разбор аргументов

- Путь пустой → спросить один раз, какой проект.
- `--fix` отсутствует → **режим наблюдения**: находки в реестр, правок нет.
- `--fix` есть → режим правок, но только после ворот Шага 0.

## Шаг 0. Ворота — без git не начинаем

```bash
cd <проект> && git rev-parse --is-inside-work-tree
```

Не репозиторий и запрошен `--fix` → **отказать**, предложить `git init` +
baseline-коммит. Не репозиторий и режим наблюдения → идти дальше, пометив
в отчёте, что правки заблокированы.

## Шаг 1. Срез

```bash
python3 ~/.claude/tools/repo-inventory/inventory.py <проект>
```

Кладёт `<проект>/.inventory/`. Занимает 3–15 с.
**Ворота:** в разделе «1а. Покрытие» сумма корзин сходится с числом файлов.
Скрипт печатает `❌ РАСХОЖДЕНИЕ`, если нет — тогда стоп, чинить скрипт.

## Шаг 2. Нарезка зон

Прочитать **только** `.inventory/00_MAP.md`. Код в главную сессию не читать
ни при каких обстоятельствах.

Нарезать на зоны: ≤3 000 строк или ≤12 файлов, что раньше. Порядок —
горячие зоны, потом зоны с находками, потом CC ≥ 21, потом остальное.
Записать таблицу зон в `.inventory/05_REESTR.md` по шаблону из регламента.

## Шаг 3. Волны

По 5 субагентов параллельно, одна зона на субагента. В задание каждому:
список файлов зоны (пути, не содержимое) + выдержка из `02_findings.json`
по этой зоне + потолок сводки **2 000 токенов**.

После каждой волны — дописать находки в реестр, проверить свой размер.
Больше **70 000 токенов** → `/clear`, перечитать `00_MAP.md` и
`05_REESTR.md` с диска, продолжить. Не `/compact` — он сам дорогой.

## Шаг 4. Ворота

- Зоны со вердиктом «чисто» → `silent-failure-hunter`. Без него «чисто»
  не засчитывается.
- Зоны с находками → `code-reviewer`.

Находка без подтверждения цитатой из кода в правки не идёт.
**Максимум 3 итерации на зону**, дальше — эскалация пользователю.

## Шаг 5. Правки (только с `--fix`)

Ветка `review/<дата>-<зона>` → тесты зелёные ДО → мутационная проверка ДО →
правки по одному классу за коммит → тесты ПОСЛЕ → мутационная проверка
ПОСЛЕ (kill-set не сократился).

Автоматом разрешено только: форматирование и `ruff check --fix` (safe).
**Мёртвый код никогда не удаляется автоматом** — только список кандидатов
с проверкой семи путей вызова (динамический импорт, `getattr`, reflection,
entry point, DI, реестр плагинов, строка в конфиге).

## Шаг 6. Отчёт пользователю

Сводка ≤250 слов: объём и сжатие в токенах · сколько зон и волн · топ-5
находок с классом · что заблокировано и почему. Потом меню:

- **A** — применить безопасные правки сейчас
- **B** — оформить задачей, отложить
- **C** — только реестр, обсудим позже

## Если срез уже есть

`.inventory/00_MAP.md` моложе суток → не пересобирать, спросить
«срез от <время>, обновить?».
