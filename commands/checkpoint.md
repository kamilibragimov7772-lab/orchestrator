# /checkpoint

Сохрани промежуточную точку текущей сессии. Сессия не закрывается — это snapshot для возврата позже / для другой вкладки / для passing baton.

## Что делать

1. Определи `currentDate` из контекста (не выдумывай).

2. Сформируй summary без вопросов мне (auto-call, не блокируй):
   - **Контекст:** проект / клиент / задача (1 строка)
   - **Сделано:** буллет-список конкретных результатов сессии до этой точки (макс 5)
   - **В работе:** что сейчас активно (1-3 пункта)
   - **Блокирует:** что мешает идти дальше (если есть)
   - **Открытые вопросы:** что я тебя ещё не спросил / что ждёт моего ответа
   - **Следующий шаг:** один конкретный пункт, с которого продолжить
   - **Артефакты:** список путей к файлам, созданным в сессии (если есть)

3. Сохрани в `<VAULT_ROOT>\11-Decisions-Log\<YYYY-MM-DD>.md`:
   - Если файл за сегодня уже есть — допиши секцию `## Checkpoint <HH:MM> — <slug>`
   - Если нет — создай с frontmatter `type: checkpoints` и одной секцией

3-bis. **Resumable state (переносимый примитив, для возобновления после сбоя/в другой вкладке).** Если идёт `/orchestr`-прогон или Workflow-фан-аут — продублируй точку в run-лог `<VAULT_ROOT>/_orchestr/_ACTIVE/run-*.md` секцией `## Checkpoint` в ФИКСИРОВАННОМ формате, чтобы новая сессия возобновилась с шага N, а не с нуля:
   ```yaml
   resume_state:
     completed_steps: [<какие шаги/волны завершены>]
     in_flight: <текущий шаг/волна>
     next_node: <конкретное следующее действие>
     artifacts: [<пути готовых артефактов>]
     workflow_run_id: <wf_... если был Workflow — для resumeFromRunId>
   ```
   Для упавшего Workflow укажи `workflow_run_id` — возобновление через `Workflow({scriptPath, resumeFromRunId})` вернёт завершённых агентов из кэша, доработают только упавшие.

4. Если `$ARGUMENTS` непустой — используй как `<slug>` для названия секции.
   Если пустой — сгенери slug из 2-3 слов по теме сессии.

5. Покажи мне:
   - Путь к файлу
   - 5-7 строк сжатой версии (для копирования в другую вкладку / Telegram)
   - В конце — «Следующий шаг: <X>»

## Чего НЕ делать

- НЕ закрывать сессию, НЕ запускать knowledge-curator / Stop-хук (это для финала, а это middle-snap)
- НЕ требовать ответа пользователя — это автомат
- НЕ переписывать уже существующий checkpoint того же часа — допиши с инкрементом времени `## Checkpoint 14:32`

## Применяется когда

- Большая задача растягивается на 2+ часа
- Пользователь уходит на встречу/созвон, надо вернуться к продолжению
- Сессия близка к лимиту контекста, но задача не закончена
- Нужно передать состояние в другую вкладку Claude Code

## Примеры

- `/checkpoint` — автоматический snap текущей точки
- `/checkpoint <проект> merge готов, проверка тестов осталась` — с явным slug
