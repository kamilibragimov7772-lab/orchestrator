# Канон входного файла проекта

> **Версия:** 1.0 · **Создан:** 2026-07-31
>
> Подгружается ТОЛЬКО при создании нового проекта или правке входного файла. В остальное время не нужен — это lazy-файл, как `_orchestr_protocol.md`.

Этот канон говорит, **что** класть во входной файл. Как формулировать, чтобы агент исполнял (указатели и их ветки, лестница информации, критерии завершения, ведущие слова, прополка пустышек и дублей) — `_writing_for_agents.md` (внешняя зависимость, см. README). Читать вместе с этим файлом, а также когда правишь карточку агента, скил или `CLAUDE.md`.

## Зачем файл существует

Каждая сессия Claude Code стартует с пустым контекстом. Без входного файла первые 10-20 тысяч токенов уходят на разведку: что за проект, чем запускается, где что лежит. Контекст — главный дефицит; чем он полнее, тем хуже качество. Входной файл снимает эту разведку.

**Он пишется для машины, не для человека.** Критерий качества не «понятно и красиво», а «за один Read сессия не наделает ошибок».

## Правило №1 — тест на каждую строку

> **«Если это убрать — Claude начнёт ошибаться?»** Нет → строки быть не должно.

Это дословный критерий Anthropic, и он жёстче, чем кажется. Раздутый входной файл — **named failure pattern**: «If your CLAUDE.md is too long, Claude ignores half of it because important rules get lost in the noise». То есть лишняя строка не нейтральна — она вытесняет нужную.

**Ориентир: 200 строк.** Дословно у Anthropic — «target under 200 lines… longer files consume more context and reduce adherence». Это цель, а не механический лимит: `CLAUDE.md` грузится **целиком независимо от длины** («CLAUDE.md files are loaded in full regardless of length»). Жёсткая отсечка на 200 строк / 25 КБ есть только у `MEMORY.md` (авто-память) — не путать. Больше 200 — не «обрежется», а перестанет исполняться.

## Разделительная ось — выводимость, а не тема

> **Единственный критерий: выводится ли это из кода за пару чтений.** Выводится → не пишем. Не выводится → пишем, какой бы «архитектурной» тема ни была.

Это важно, потому что тематический запрет — ошибка. Дока **не** запрещает архитектуру и раскладку проекта: в списке «✅ Include» прямо стоит «architectural decisions specific to your project», а `/memory` требует держать «build commands, conventions, **project layout**, "always do X" rules» и «coding standards, workflows, **project architecture**».

Запрещено другое — то, что модель добудет сама:

- **пофайловое** описание кодовой базы (дословный запрет: «file-by-file descriptions of the codebase»);
- дерево папок, воспроизводящее `ls -R`;
- список зависимостей, переписанный из `package.json` / `requirements.txt`;
- обзор архитектуры, пересказывающий структуру импортов.

Разница на примере. ❌ «`src/api/` — обработчики, `src/db/` — модели, `src/utils/` — утилиты» (это `ls`). ✅ «Бизнес-логика живёт только в сервисах; обработчики обязаны оставаться тонкими — если логика поехала в handler, это баг ревью, а не стиль» (это решение, из кода не читается).

## Что класть (прошло тест)

| Секция | Почему выживает |
|---|---|
| **Куда вносить правки** | «Меняешь X → правь файл Y». Главная секция, ради неё файл окупается на масштабе. Из кода не выводится — это карта намерения, а не структуры |
| **Точки входа** | Как запустить, собрать, задеплоить. Точные команды, venv, порт, обязательные переменные. Угадать нельзя |
| **Инварианты и грабли** | Что сломается при наивном подходе. Каждая строка сюда попадает после того, как ошибка случилась дважды |
| **Внешние связи** | Сервер, юнит, порт, домен, **пути** к кредам (никогда значения), смежные проекты |
| **Договорённости, отличные от дефолта** | Только то, что расходится со стандартом языка/фреймворка. Совпадающее с дефолтом — не писать |

## Что НЕ класть (и куда это девать)

Список Anthropic, дословно из доки, плюс наш вывод куда переезжает содержимое:

| Не класть | Почему | Куда вместо |
|---|---|---|
| **Пофайловые описания кодовой базы** | дословный запрет доки; выводится чтением | никуда, не пишется |
| **Дерево папок вместо `ls`, список зависимостей из манифеста** | выводится тривиально | никуда. Но **решение** «почему так разложено» — писать, оно не выводится |
| **Журнал решений, историю** | не нужен каждой сессии | `11-Decisions-Log/` в vault либо `DECISIONS.md` рядом (упоминать путём, не импортом) |
| **Длинные объяснения, туториалы** | съедают лимит | ссылка на доку |
| **Стандартные конвенции языка** | модель их знает | никуда |
| **Часто меняющееся** | протухает быстрее, чем обновляется | никуда |
| **Детальную документацию API** | дословный запрет доки | ссылка на доку |
| **Секреты, токены, пароли** | утечка | только **путь** к файлу с ними |

**Чистка существующего файла:** `/doctor` **предлагает** трим (proposes trims — предлагает, не режет сам), и режет он по той же оси «выводимо из кода». Две оговорки, которые легко потерять: работает по **закоммиченному** файлу (проект вне git — трима не будет) и требует Claude Code **v2.1.206+**.

> **Ошибка, из которой это правило родилось:** в глобальный `CLAUDE.md` был вписан 7-пунктовый шаблон с «картой файлов» и «журналом решений». Оба пункта дока называет прямо тем, что класть не надо. Сочинённая структура выглядела разумно и была неправильной — отсюда требование сверяться с источником, а не с логикой.

## Три носителя — что где

| Носитель | Когда грузится | Для чего |
|---|---|---|
| **`CLAUDE.md` в корне** | **каждую сессию**, целиком; переживает `/compact` | только то, что нужно всегда. Это дефицитное место |
| **`.claude/rules/*.md`** с frontmatter `paths:` | когда агент **касается** подходящего файла | всё path-специфичное: правила по API, по тестам, по фронту |
| **`AGENTS.md`** | **Claude Code его НЕ читает** | открытый стандарт (Linux Foundation, 60k+ проектов) для Cursor/Copilot/Codex/Gemini CLI. Нужен мост |

**Мост к AGENTS.md** — первой строкой в `CLAUDE.md`:
```markdown
@AGENTS.md

## Claude Code
<специфичное для Claude>
```
Симлинк тоже работает, но **на Windows требует админа или Developer Mode** — там берём импорт.

Заводить `AGENTS.md` заранее не нужно: он окупается только когда в проект реально ходят чужие агенты.

**Важно про `@`-импорты:** импортированный файл грузится в контекст при старте **целиком**. Импорт помогает организации, но **контекст не экономит** — дословно: «splitting into `@path` imports helps organization but doesn't reduce context, since imported files load at launch».

Отсюда два способа НЕ грузить лишнее:

- **Штатный — skill.** «For domain knowledge or workflows that are only relevant sometimes, use skills instead. Claude loads them on demand without bloating every conversation.» Если материал большой и нужен изредка — это skill, а не импорт.
- **Ручной — упоминание путём.** Путь в обратных кавычках (`` `путь` ``) импорт не запускает: парсер импортов пропускает код-спаны. Модель просто прочитает файл, когда он понадобится. Так подключены этот канон и `_orchestr_protocol.md` — работает, но это ручной паттерн; ленивой загрузки как механизма тут нет, есть отсутствие загрузки.

## Порог применимости — что считается проектом

| Объект | Входной файл |
|---|---|
| Живой сервис (юнит, порт, деплой) | **обязателен** |
| Кодовая база, куда вернёмся | **обязателен** |
| Спящий проект | усечённый: что это · почему спит · как оживить (3-6 строк) |
| Одноразовый скрипт, генератор-одностраничник | не нужен |
| Папка с документами, не код | не нужен |

## Шаблон

Копировать целиком не надо — брать секции, которые проходят тест. Пустая секция хуже отсутствующей.

```markdown
# <Проект> — вход для Claude Code

<2-3 строки: что это, для кого, состояние (прототип / боевое)>

## Запуск
- dev: `<команда>` (venv `<путь>`, порт `<N>`)
- прод: сервис `<unit>` на `<хост>`, рестарт `<команда>`
- переменные: `<путь к .env>` — значения не дублировать

## Куда вносить правки
| Хочешь изменить | Правь |
|---|---|
| <поведение> | `<файл>` |
| <данные/схему> | `<файл>` |

## Грабли
- <что сломается при наивном подходе и почему>

## Внешние связи
- <сервер / порт / домен / смежный проект>
- креды: `<путь>`

## Не трогать
- <сгенерированное, вендорское, бэкапы>
```

## Второе правило — проверяй факт командой, не переноси из памяти

> **Тест на нужность строки ничего не говорит о её истинности.** Строка может пройти «если убрать — начнёт ошибаться?» и при этом быть ложной — тогда она хуже отсутствующей.

Это не теория: при первой раскатке канона на девяти проектах одного сервера **четыре** факта оказались перенесены из памяти и не соответствовали реальности — не тот класс сервиса, несуществующая строка crontab, авторизация, «переехавшая» со старого сервера только на бумаге, отсутствующий файл переменных, из-за которого таймер поднялся бы и молча молчал.

Правило простое: **факт о среде** (порт, юнит, авторизация, наличие git, что где запускается) попадает в файл только после того, как ты выполнил проверяющую команду **в этой сессии**. Не из памяти, не из README, не из прошлого прогона — они устаревают молча.

Если проверить нельзя — пиши честно: «связь не выяснена», «не проверялось». Это дешевле, чем уверенное враньё, которому следующая сессия поверит.

## Обновление — главное правило

> **Устаревший входной файл хуже отсутствующего: он врёт с уверенным лицом, и сессия ему верит.**

Файл обновляется **в той же сессии**, где менялся проект. Не «потом», не «при случае». Механика чтения гарантирована (Claude Code сам подставляет корневой `CLAUDE.md`), механика обновления — нет, поэтому она вынесена в хук `entry-file-guard.ps1`, а не оставлена на память.

Правило Anthropic про наполнение: **Claude ошибся второй раз в одном и том же месте → строка в файл.** Так он становится живой записью особенностей проекта, а не документацией впрок.

## Как заводить

1. `/init` в корне проекта — читает код и собирает черновик сам. Руками с нуля не писать: дешевле отредактировать черновик.
   > **Честно про расхождение:** HumanLayer в своей статье держит противоположную позицию — раздел «Don't use /init or auto-generate your CLAUDE.md», аргумент в том, что автогенерация тянет в файл выводимое из кода. Мы берём `/init` как **старт**, а не как результат: шаги 2-3 ниже существуют ровно затем, чтобы это выводимое вырезать. Если черновик после чистки почти пуст — значит писать было нечего, и это тоже ответ. Если файл уже есть, `/init` его не перезаписывает, а предлагает улучшения. Под `CLAUDE_CODE_NEW_INIT=1` идёт интерактивный многофазный режим и подхватываются чужие форматы правил (`AGENTS.md`, Cursor, Copilot, Windsurf, Cline).
2. Прогнать черновик по тесту «если убрать — начнёт ошибаться?», вырезать всё, что не проходит.
3. Дописать то, что из кода не выводится: грабли, договорённости, внешние связи, решения.
4. Проверить объём: ориентир 200 строк.
5. **Обратный тест приёмки:** свежая сессия по этому файлу поднимает проект **без дочитывания кода**. Не прошёл — файл не готов, сколько бы секций в нём ни было.

Существующий раздутый файл: `/doctor` предложит трим (см. оговорки выше).
