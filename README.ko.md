# Orchestrator — 검증 가능한 Claude Code 오케스트레이션 스택

**[English](README.en.md) · [Русский](README.md) · [简体中文](README.zh-CN.md) · [Español](README.es.md) · [Português](README.pt-BR.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Deutsch](README.de.md) · [Français](README.fr.md) · [हिन्दी](README.hi.md) · [العربية](README.ar.md) · [Türkçe](README.tr.md)**

Claude Code 세션 하나를 오케스트레이터로 바꿉니다. 브리프가 웨이브 계획이 되고, 각 웨이브는
전문 서브에이전트를 실행하며, 모든 웨이브는 파일로 떨어지고, 마지막에 독립된 리뷰어가
결과를 수용할지 반려할지 판정합니다. 에이전트 카드 41장, 공유 계약 10개, 슬래시 명령 10개,
선택 스킬 4개.

MIT 라이선스. 작성자: **[@kamil_ibrgmv](https://instagram.com/kamil_ibrgmv)**. 프로토콜 **2.16.0**.

> **먼저 읽어 주세요 — 언어 안내.** 오케스트레이션 프로토콜, 에이전트 카드, 수용 기준은
> **러시아어**로 작성되어 있습니다. 도구, 테스트, 설치 경로, 코드 주석은 영어입니다.
> 에이전트 자체가 목적이라면 러시아어 마크다운을 읽게 됩니다. 에이전트 스택을 신뢰할 수 있게
> 만드는 배관이 목적이라면, 그 부분은 언어와 무관하며 이 저장소가 존재하는 이유입니다.

## 왜 만들었나

Claude Code 서브에이전트 모음은 부족하지 않습니다. 부족한 것은 **검증할 수 있는** 모음입니다.
대부분은 마크다운 파일 폴더일 뿐입니다. 훅이 실제로 실행됐다는 증거도, 시크릿 스캐너가 올바른
바이트를 보고 있다는 증거도 없고, 어떤 검사가 조용히 멈춰도 아무것도 실패하지 않습니다.

이 저장소는 반대의 선택을 했습니다. 에이전트 라이브러리는 평범하고,
**그 주변의 배관이 핵심**입니다.

| 대부분의 모음이 주는 것 | 이 저장소가 주는 것 |
|---|---|
| 에이전트 마크다운뿐 | 에이전트 **＋** 가드, 설치기, 진단기, 수용 게이트, 동기화 |
| 테스트 없음 | **테스트 97개**. 표준 라이브러리만, API 호출 없음, 네트워크 없음 |
| 「이걸 settings.json에 추가하세요」 | 충돌 사전 점검이 있는 설치기. **진단기가 가드를 실제로 실행**하고 차단할 것을 요구 |
| 훅이 동작한다고 가정 | 3개 페이로드 스모크 테스트: 정상은 통과, 시크릿은 차단, 위험 명령은 차단 |
| 「안전합니다, 프롬프트를 믿으세요」 | 프롬프트 문구를 접근 경계로 취급하지 않음 — [SECURITY.md](SECURITY.md) 참고 |

스크립트로 확인할 수 있는 것은 전부 스크립트가 확인합니다.
프롬프트 안에만 사는 규칙은 조용히 지켜지지 않게 되는 규칙이기 때문입니다.

## 빠른 시작

**Python 3.10 이상**과 **Git**이 필요합니다. API 키 불필요, 네트워크 불필요, 모델 호출 없음:

```sh
git clone https://github.com/kamilibragimov7772-lab/orchestrator
cd orchestrator
python tools/verify.py
```

에이전트 계약 린터, 준비도 카운터 자체 테스트, 전체 테스트 스위트, 시크릿 스캔을 실행합니다.
체크아웃 바깥은 건드리지 않습니다.

직접 고른 디렉터리에 설치합니다. 설치기는 **먼저 계획을 보여 주고 절대 덮어쓰지 않습니다**:

```sh
python tools/install.py \
  --destination /absolute/path/stack \
  --vault /absolute/path/knowledge-base \
  --mode minimal
```

계획을 확인한 뒤 `--apply`를 붙여 다시 실행하세요. 대상 파일이 이미 있고 내용이 다르면 설치가
중단되고 기존 파일이 보존됩니다. 그다음 결과를 확인합니다:

```sh
python tools/doctor.py --root /absolute/path/stack --installed
```

`minimal`은 리서치와 마크다운 산출물을 위한 7개 역할을 설치합니다. `full`은 소프트웨어 /
사이트 빌드 / 미디어 파이프라인과 그 외부 의존성을 추가합니다. Windows 관련 사항과 Claude
Code를 새 디렉터리로 연결하는 방법은 [INSTALL.md](INSTALL.md)를 보세요.

## 구성

| 계층 | 역할 | 검증 경계 |
|---|---|---|
| `_orchestr_protocol.md`, `agents/`, `commands/` | 라우팅, 계약, 완료 정의 | 린터는 구조를 검사. 답변 품질은 사람의 수용이 필요 |
| `tools/verify.py`, `tests/` | 재현 가능한 단일 명령, 부정 케이스 포함 | Claude API 없음, 외부 MCP 없음 |
| `tools/guard.py` | PreToolUse 단계의 자격 증명·파괴적 명령 탐지 | **휴리스틱 심층 방어** — 호스트 권한과 샌드박스를 유지할 것 |
| `tools/install.py`, `tools/doctor.py` | 비파괴 설치, 준비 상태 보고 | 진단기는 인증도 모델 품질도 검사하지 않음 |
| `tools/acceptance-gate/` | 실행 로그의 결정론적 검사 + 선택적 리뷰어 워커 | 모델 워커는 **기본 비활성**. 실제 E2E는 미인증 |
| `tools/sync_stack.py` | 정확한 허용 목록 기반 Git 브리지 | 선택 사항. 갈라진 브랜치를 대신 병합하지 않음 |
| `tools/export_session.py` | 옵트인 방식 대화 기록 내보내기 | **비활성**. 마스킹은 패턴 기반이며 프라이버시 보장이 아님 |

### 수용 게이트

가장 오래 다듬은 부분입니다. 실행이 종료되면 **별도의 컨텍스트**——오케스트레이터의 추론을
전혀 보지 않은——가 브리프에 비추어 산출물을 판정합니다. 결정론적 스크립트가 먼저 돌고,
모델은 스크립트가 판단할 수 없는 부분만 봅니다.

- `run_status`와 `verdict`는 서로 다른 필드입니다. `done`이 아닌 실행은 *「수용 대상 아님」*을
  반환하며, 가짜 합격을 내지 않습니다.
- `SKIP`은 **「불완전」**이 되며 결코 「수용」이 되지 않습니다. PDF는 *서명만 확인 — 뷰어에서
  열 것*으로, `.docx`는 *구조는 파싱됨, 시각적 수용은 별도*로 보고됩니다.
- 종료 코드가 구분됩니다: `0` 수용 · `1` 반려 · `3` 불완전 · `4` 해당 없음 · `2` 오류.

근거는 작성자가 259회 실행에서 측정한 수치입니다. 검증기에 들어간 규칙은 76~100% 지켜졌고,
같은 규칙을 프롬프트 문구로만 두었을 때는 0~39%였습니다.

## 의도적으로 하지 않는 것

신뢰란 대체로 「그 도구가 몰래 하지 않는 일」의 목록입니다.

- **설치 시 자동 내보내기, 미러링, Git push, cron, 모델 프로세스를 하나도 켜지 않습니다.**
  모두 옵트인이며 명시적 설정이 필요합니다.
- **`robocopy /MIR` 방식의 미러링은 없습니다.** 원본에 없는 파일을 대상에서 삭제할 수 있어
  제거했습니다.
- **덮어쓰지 않습니다.** 충돌 파일이 있으면 설치가 멈추고, 설정과 훅은 교체가 아니라 병합됩니다.
- **조용한 합격은 없습니다.** 의존성 누락이나 미실행 검사는 `NOT CHECKED` 또는 `SKIP`으로
  보고됩니다. 얻지 못한 합격을 보고하는 일은 없습니다.
- **증명하지 못한 점수를 주장하지 않습니다.** 「9.5/10」은 목표였고 **인증되지 않았습니다**.
  미해결 항목은 평균으로 희석하지 않고 [`audit_9_5/`](audit_9_5/)에 나열해 두었습니다.

## 검증 현황

CI는 Windows / Linux / macOS × Python 3.10 및 3.12에서 실행되고, 모든 PowerShell 스크립트를
파싱하며, **Git 히스토리 전체**를 Gitleaks로 스캔합니다.
[`.github/workflows/ci.yml`](.github/workflows/ci.yml)를 보세요.

초록 배지는 증거가 아니므로 한계도 솔직히 적습니다.

- 테스트는 도구의 동작을 다루며, 에이전트가 작성한 내용의 품질은 다루지 않습니다.
- 실제 모델을 쓰는 E2E 수용은 스위트에 **포함되어 있지 않습니다**.
- 가드는 휴리스틱입니다. 호스트 권한을 보완할 뿐 대체하지 않습니다.

## 방법론적 근거

엔지니어링 기준은 **NIST SSDF 1.1**(NIST, 2022)——결함을 재현하고, 고치고, 깨진 케이스를
거부하는 회귀 테스트를 추가한다——그리고 호스트 공식 문서
([Claude Code hooks](https://code.claude.com/docs/en/hooks))입니다. 2026-09-06 확인.
SSDF는 위험을 선별하는 데 사용했을 뿐, 준수 인증으로 내세우지 않습니다.
