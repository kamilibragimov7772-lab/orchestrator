# acceptance-gate — «босс», который принимает работу

Приёмщик закрытого прогона оркестратора. Стоит **над** оркестратором: запускается
после того, как прогон объявлен готовым, отдельным контекстом, который видит
только ТЗ и артефакты и не видит рассуждений автора.

Зачем именно так — два измерения из этого же стека:

- **259 прогонов** (`_orchestr_protocol` 2.14.2): правило, попавшее в валидатор,
  держится на 76–100%; то же правило текстом в промпте — на 0–39%.
- **48 доработок одного клиентского продукта** (`_gotovo_canon.md`): 46% брака — известный
  стандарт, который автор знал и не применил. Лечится только проверкой,
  которую проходит **не автор**.

Отсюда конструкция: всё, что проверяется машиной, проверяет машина; модель судит
только то, что машиной не берётся.

## Из чего состоит

| Файл | Где живёт |
|---|---|
| `checks.py` | `tools/acceptance-gate/` — детерминированное ядро, только стандартная библиотека |
| `acceptance-gate.ps1` | `tools/acceptance-gate/` — Stop-хук для Windows / PowerShell |
| `agents/acceptance-gate.md` | `agents/` — карточка приёмщика |
| `commands/priyomka.md` | `commands/` — ручной запуск |
| регистрация в `settings.json` | делается руками на каждой машине (см. ниже) |

Пути: корень vault скрипт и хук берут из переменной окружения `VAULT_ROOT`
(по умолчанию `~/vault`), каталог стека — из `CLAUDE_HOME` (по умолчанию `~/.claude`).

## Как пользоваться

**Автоматически.** Stop-хук после каждой сессии смотрит `<VAULT_ROOT>/_orchestr/_ACTIVE/`:
нашёл прогон со `status: done` и без секции `## Приёмка` — запускает приёмку фоном.
На обычных сессиях молчит.

**Руками.** `/priyomka` — на последнем закрытом прогоне, или `/priyomka <run_id>`.

**Только скрипт, без модели.** Быстрая проверка без затрат на прогон:

```
python3 ~/.claude/tools/acceptance-gate/checks.py <путь-к-run-логу>
```

Коды возврата: `0` принято · `1` не принято · `3` неполно · `4` не подлежит
приёмке (`status ≠ done`) · `2` ошибка вызова.

## Режим

Сейчас **report-only**: хук пишет вердикт в run-лог и никогда не блокирует
остановку сессии. Это первая ступень лестницы «сначала только отчёты, потом
действия с подтверждением, автономия — после статистики надёжности».
Ужесточать до блокирующего — отдельным решением, после нескольких прогонов.

## Выключить

- Разово: создать файл `~/.claude/.acceptance-gate-off`
- Совсем: убрать блок `"hooks"` из `~/.claude/settings.json`

## Регистрация на ноутбуке (делается один раз)

В `%USERPROFILE%\.claude\settings.json` добавить ключ верхнего уровня:

```json
"hooks": {
  "Stop": [
    {
      "matcher": "*",
      "hooks": [
        {
          "type": "command",
          "command": "powershell -NoProfile -ExecutionPolicy Bypass -File \"%USERPROFILE%\\.claude\\tools\\acceptance-gate\\acceptance-gate.ps1\"",
          "timeout": 20
        }
      ]
    }
  ]
}
```

Проверка холостым ходом, без запуска приёмки и без трат:

```powershell
$env:ACCEPTANCE_GATE_DRYRUN=1
'{}' | powershell -NoProfile -File "$HOME\.claude\tools\acceptance-gate\acceptance-gate.ps1"
```

Должно ответить `DRY-RUN: подходящего прогона нет` либо назвать прогон, на
котором сработало бы.

> ⚠️ Если правишь `.ps1` на ноуте — сохраняй **UTF-8 с BOM**. PowerShell 5.1
> читает файл без BOM как cp1251 и ломает кириллицу. Эти грабли уже оплачены.

## Чего он НЕ делает

- Не чинит найденное — только называет.
- Не закрывает уровень `боевой`. Его потолок — `рабочий`. «Сдано = открыто тем
  путём, каким откроет получатель», а он открывает путём скрипта.
- Не судит прогон в работе (`status ≠ done`).
