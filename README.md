# Orchestrator — стек оркестрации для Claude Code

Русскоязычный протокол: бриф → план волн → специализированные агенты → артефакты → проверка → приёмка. В поставке 41 карточка агента, 10 общих контрактов, 10 команд и 4 опциональных скила. Автор — **@kamil_ibrgmv**; лицензия [MIT](LICENSE).

Версия протокола: **2.16.0**. Локальная ветка hardening от 2026-09-06 добавляет воспроизводимые проверки и безопаснее настраиваемые инструменты. Это кандидат на проверку; рейтинг 9,5 не сертифицирован. Доказательства и оставшиеся ограничения — [audit_9_5/00_EXECUTIVE_SUMMARY.md](audit_9_5/00_EXECUTIVE_SUMMARY.md).

## Начало работы

Нужны Python 3.10+ и Git. Проверка исходников без моделей и платных API:

```sh
python tools/verify.py
```

Установщик сначала показывает план. Явно выберите отдельные каталоги стека и базы знаний:

```sh
python tools/install.py --destination /absolute/path/stack --vault /absolute/path/vault --mode minimal
```

`minimal` рассчитан на исследования и Markdown-документы: семь ролей, без software/site/media pipeline. Перед запуском проверьте наличие требуемых ролей; расширенные сценарии требуют `full` и их внешних зависимостей.

Добавьте `--apply`, чтобы применить этот план. Конфликтующие файлы сохраняются, установка останавливается. Настройка Claude Code и Windows-команды — [INSTALL.md](INSTALL.md).

## Состав и границы

| Слой | Назначение | Граница проверки |
|---|---|---|
| `_orchestr_protocol.md`, `agents/`, `commands/` | Маршрутизация, контракты, критерии готовности | Линтер проверяет часть структуры; качество реального ответа требует отдельной приёмки |
| `tools/verify.py`, `tests/` | Воспроизводимые проверки и негативные сценарии | Без Claude API и внешних MCP |
| `tools/guard.py` | Дополнительное распознавание секретов и опасных команд | Эвристика; сохраняйте разрешения и sandbox хоста |
| `tools/install.py`, `doctor.py` | Установка без затирания, проверка путей и зависимостей | Doctor не проверяет авторизацию и качество модели |
| `tools/acceptance-gate/` | Детерминированная проверка и отдельный worker | Model-worker выключен по умолчанию, live E2E не подтверждён |
| `tools/sync_stack.py` | Git-синхронизация по точному allowlist | Опциональна; не объединяет разошедшиеся ветки автоматически |
| `tools/export_session.py` | Управляемый экспорт транскриптов | Выключен; redacted не гарантирует удаления персональных данных |
| Медиа, site-build, geo-parser | Дополнительные сценарии | Отдельные зависимости, входы и проверка результата |

Установка включает только два PreToolUse guard. Автоэкспорт, зеркало папок, Git-push и запуск модели не включаются. Старое зеркалирование через `/MIR` удалено. `entry-file-guard.ps1` сохранён как legacy-инструмент Windows и автоматически не регистрируется.

## Разработка

[AGENTS.md](AGENTS.md) — вход для работы с кодом. [CONTRIBUTING.md](CONTRIBUTING.md) — команды проверки; [SECURITY.md](SECURITY.md) — ограничения защит и экспорт; [CHANGELOG.md](CHANGELOG.md) — изменения поведения.

CI описывает Windows/Linux/macOS × Python 3.10/3.12, PowerShell parse и Gitleaks всей Git-истории. Наличие workflow не доказывает успешный запуск CI или защиту main. Codex-совместимость описана отдельно в [08_CODEX_PORTABILITY.md](audit_9_5/08_CODEX_PORTABILITY.md).
