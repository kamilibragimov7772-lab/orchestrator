# Релизный чек-лист

Порядок закрытия релиза. Пункт считается закрытым, только когда названа команда
и её результат воспроизводим на конкретном commit SHA. «Проверено глазами» и
«должно работать» пунктов не закрывают.

Правило, которое дороже остальных: **непройденная или невыполненная проверка не
может отображаться как пройденная.** Пропуск допустим, но обязан нести причину и
попадать в итог как пропуск, а не растворяться в среднем балле.

## 1. Локально, без модели и без сети

| Что | Команда | Порог |
|---|---|---|
| Юнит и регрессии | `python tools/verify.py` | все зелёные, ни один тест не удалён ради зелени |
| Предупреждения как ошибки | `python -W error::ResourceWarning -m unittest discover -s tests` | 0 предупреждений своего кода |
| Карточки агентов | `python tools/agent-lint.py --quiet` | ОШИБОК: 0 |
| Сценарии приёмки без модели | `python tools/e2e/harness.py --offline` | 0 fail; пропуски названы |
| Скан рабочего дерева | `python tools/secret_scan.py --root .` | `findings: []` |
| Установка вхолостую | `python tools/install.py --destination <tmp> --vault <tmp> --mode minimal` | ни одного файла не создано |
| Установка и доктор | те же с `--apply`, затем `python tools/doctor.py --root <tmp> --installed` | нет `fail`; отсутствующее названо |
| Повторная установка | повторить `--apply` | список файлов не изменился (без `__pycache__`) |

## 2. С моделью, на одноразовом vault

| Что | Команда | Порог |
|---|---|---|
| Живые сценарии приёмки | `python tools/e2e/harness.py --live --budget 4` | 6 обязательных сценариев пройдены, инъекция получила `rejected` |
| Бенчмарк семи ролей | `python tools/benchmark/roles.py --run --budget 28` | средний ≥9,0; ни одна роль <8,5; жёсткие ворота 100%; ложных PASS нет |

Оба пункта тратят платные вызовы. Бюджет объявляется до запуска и не повышается
задним числом; исчерпание бюджета даёт `skipped` с причиной, а не повтор.

## 3. Удалённо

| Что | Как | Порог |
|---|---|---|
| CI на точном SHA | `gh pr checks <PR>` | все обязательные проверки зелёные на HEAD кандидата |
| Матрица | тот же вывод | Windows / Linux / macOS × Python 3.10 / 3.12 |
| История на секреты | job `security` | Gitleaks по всей истории и рабочему дереву |
| Защита `main` | `gh api repos/<owner>/<repo>/rules/branches/main` | `deletion`, `non_fast_forward`, `pull_request`, `required_status_checks` |
| Защита работает | `gh pr view <PR> --json mergeStateStatus` | `BLOCKED` при красном CI, `CLEAN` при зелёном |

## 4. Согласованность поставки

- [ ] Версия одна и та же в `README.md`, `AUTHORS.md`, `_orchestr_protocol.md`, `CHANGELOG.md`.
- [ ] `CHANGELOG` описывает изменения поведения, а не список файлов.
- [ ] Карточки не описывают режим, которого больше нет; там, где путей два, названы оба и их разные гарантии.
- [ ] `SECURITY.md` не обещает свойства, которого нет в коде.
- [ ] Манифест релизных файлов пересчитан: `python tools/release_manifest.py --write`.
- [ ] Отчёт релиза называет и то, что НЕ сделано, с владельцем и способом воспроизведения.

## 5. Чего не делать при закрытии

- Не понижать порог, чтобы прошло. Красное — находка.
- Не удалять и не пропускать тест ради зелёного CI.
- Не заявлять балл, под который нет прогона на этом SHA. 9,42 не округляется до 9,5.
- Не мержить PR и не ставить тег без явного решения владельца.
- Не переписывать опубликованную историю.
