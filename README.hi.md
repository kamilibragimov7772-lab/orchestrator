# Orchestrator — Claude Code के लिए एक सत्यापन-योग्य ऑर्केस्ट्रेशन स्टैक

**[English](README.en.md) · [Русский](README.md) · [简体中文](README.zh-CN.md) · [Español](README.es.md) · [Português](README.pt-BR.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Deutsch](README.de.md) · [Français](README.fr.md) · [हिन्दी](README.hi.md) · [العربية](README.ar.md) · [Türkçe](README.tr.md)**

एक Claude Code सत्र को ऑर्केस्ट्रेटर में बदल देता है: एक ब्रीफ़ से वेव-प्लान बनता है, हर वेव में विशेषज्ञ
सब-एजेंट चलते हैं, हर वेव का नतीजा फ़ाइल के रूप में उतरता है, और अंत में एक स्वतंत्र समीक्षक तय करता है
कि नतीजा स्वीकार होगा या लौटाया जाएगा। 41 एजेंट कार्ड, 10 साझा अनुबंध, 10 स्लैश कमांड, 4 वैकल्पिक स्किल।

> लिखे गए हैं। टूलिंग, टेस्ट, इंस्टॉलेशन और कोड टिप्पणियाँ अंग्रेज़ी में हैं। यदि आपको एजेंट स्वयं चाहिए, तो आपको

## यह क्यों बना

Claude Code के सब-एजेंट संग्रहों की कमी नहीं है। कमी उनकी है जिन्हें आप **सत्यापित** कर सकें। अधिकांश केवल
Markdown फ़ाइलों का एक फ़ोल्डर हैं: कुछ भी सिद्ध नहीं करता कि हुक वास्तव में चले, कुछ भी सिद्ध नहीं करता कि
सीक्रेट स्कैनर सही बाइट्स देख रहा है, और जब कोई जाँच चुपचाप जाँचना बंद कर दे तो कुछ भी विफल नहीं होता।

यह रिपॉज़िटरी उल्टा समझौता करती है। एजेंट लाइब्रेरी सामान्य है; **असली बात उसके चारों ओर का ढाँचा है**:

| ज़्यादातर संग्रह जो देते हैं | यह जो देता है |
|---|---|
| केवल एजेंट Markdown | एजेंट **और साथ में** गार्ड, इंस्टॉलर, डॉक्टर, स्वीकृति गेट, सिंक |
| कोई टेस्ट नहीं | **97 टेस्ट**, केवल स्टैंडर्ड लाइब्रेरी, कोई API कॉल नहीं, कोई नेटवर्क नहीं |
| «इसे settings.json में जोड़ दें» | टकराव की पूर्व-जाँच वाला इंस्टॉलर; **डॉक्टर गार्ड को सचमुच चलाता है** और माँगता है कि वह रोके |
| मान लिया जाता है कि हुक चलते हैं | तीन पेलोड का स्मोक टेस्ट: सामान्य पास हो, सीक्रेट रुके, ख़तरनाक कमांड रुके |
| «सुरक्षित है, प्रॉम्प्ट पर भरोसा करें» | प्रॉम्प्ट के शब्दों को कभी पहुँच-सीमा नहीं माना जाता — देखें [SECURITY.md](SECURITY.md) |

जो कुछ स्क्रिप्ट जाँच सकती है, वह स्क्रिप्ट ही जाँचती है — क्योंकि जो नियम केवल प्रॉम्प्ट में रहता है,
वह चुपचाप मानना बंद कर दिया जाने वाला नियम है।

## तेज़ शुरुआत

आवश्यक: **Python 3.10+** और **Git**। कोई API की नहीं, कोई नेटवर्क नहीं, कोई मॉडल कॉल नहीं:

```sh
git clone https://github.com/kamilibragimov7772-lab/orchestrator
cd orchestrator
python tools/verify.py
```

यह एजेंट-अनुबंध लिंटर, तैयारी-काउंटर का स्व-परीक्षण, पूरा टेस्ट सूट और एक सीक्रेट स्कैन चलाता है।
चेकआउट के बाहर किसी चीज़ को नहीं छूता।

अपनी चुनी हुई डायरेक्टरियों में इंस्टॉल करें — इंस्टॉलर **पहले योजना दिखाता है और कभी ओवरराइट नहीं करता**:

```sh
python tools/install.py \
  --destination /absolute/path/stack \
  --vault /absolute/path/knowledge-base \
  --mode minimal
```

योजना देखने के बाद `--apply` के साथ फिर चलाएँ। यदि कोई लक्ष्य फ़ाइल मौजूद है और भिन्न है, तो इंस्टॉलेशन
रुक जाता है और आपकी फ़ाइल सुरक्षित रहती है। फिर परिणाम की पुष्टि करें:

```sh
python tools/doctor.py --root /absolute/path/stack --installed
```

`minimal` शोध और Markdown डिलिवरेबल के लिए सात भूमिकाएँ स्थापित करता है। `full` सॉफ़्टवेयर / साइट-बिल्ड /
मीडिया पाइपलाइन और उनकी बाहरी निर्भरताएँ जोड़ता है। Windows संबंधी बातें और Claude Code को नई डायरेक्टरी
पर कैसे इंगित करें: [INSTALL.md](INSTALL.md)।

### स्वीकृति गेट

वह विचार जिसे ठीक करने में सबसे अधिक समय लगा। जब कोई रन बंद होता है, तब एक **अलग संदर्भ** — जिसने
ऑर्केस्ट्रेटर का तर्क कभी नहीं देखा — डिलिवरेबल को ब्रीफ़ के विरुद्ध परखता है। पहले एक निर्धारणात्मक स्क्रिप्ट
चलती है, और मॉडल केवल वही परखता है जो स्क्रिप्ट नहीं परख सकती:

- `run_status` और `verdict` अलग-अलग फ़ील्ड हैं। जो रन `done` नहीं है, वह *«स्वीकृति के दायरे से बाहर»*
  लौटाता है, नकली पास नहीं।
- `SKIP` से **«अपूर्ण»** निकलता है, कभी «स्वीकृत» नहीं। PDF को *केवल सिग्नेचर — व्यूअर में खोलें* बताया
  जाता है; `.docx` को *संरचना पार्स होती है, दृश्य स्वीकृति अलग से*।
- एग्ज़िट कोड अलग-अलग हैं: `0` स्वीकृत · `1` अस्वीकृत · `3` अपूर्ण · `4` लागू नहीं · `2` त्रुटि।

आधार, जो लेखक ने 259 रन पर मापा: जो नियम किसी वैलिडेटर तक पहुँचा, वह 76–100% बार टिकता है;
वही नियम केवल प्रॉम्प्ट के पाठ के रूप में 0–39% बार।

## यह जानबूझकर क्या नहीं करता

भरोसा अधिकतर उन चीज़ों की सूची है जो कोई औज़ार आपकी पीठ पीछे करने से इनकार करता है:

- **इंस्टॉल पर कोई स्वचालित निर्यात, मिररिंग, Git push, cron या मॉडल प्रक्रिया नहीं।** हर एक ऑप्ट-इन है और
  स्पष्ट कॉन्फ़िगरेशन माँगता है।
- **`robocopy /MIR` जैसी मिररिंग नहीं।** वह गंतव्य से ऐसी फ़ाइलें मिटा सकती थी जो स्रोत में नहीं थीं।
  उसे हटा दिया गया।
- **कोई ओवरराइट नहीं।** टकराने वाली फ़ाइलें इंस्टॉलेशन रोक देती हैं; आपकी settings और hooks मर्ज होती हैं,
  बदली नहीं जातीं।
- **कोई मौन पास नहीं।** अनुपस्थित निर्भरता या न चली जाँच `NOT CHECKED` या `SKIP` बताती है।
  बिना अर्जित किया पास कभी नहीं बताया जाता।
- **बिना प्रमाण के कोई रेटिंग का दावा नहीं।** «9.5/10» लक्ष्य था और **प्रमाणित नहीं है** — खुले बिंदु औसत में
  घोलने के बजाय [`audit_9_5/`](audit_9_5/) में सूचीबद्ध हैं।

## सत्यापन की स्थिति

CI Windows / Linux / macOS × Python 3.10 और 3.12 पर चलता है, हर PowerShell स्क्रिप्ट पार्स करता है और
Gitleaks से **पूरे Git इतिहास** को स्कैन करता है। देखें
[`.github/workflows/ci.yml`](.github/workflows/ci.yml)।

ईमानदार सीमाएँ, क्योंकि हरा बैज प्रमाण नहीं है:

- टेस्ट औज़ारों के व्यवहार को कवर करते हैं, एजेंट जो लिखते हैं उसकी गुणवत्ता को नहीं।
- असली मॉडल के साथ एंड-टू-एंड स्वीकृति सूट में **शामिल नहीं** है।
- गार्ड अनुमान-आधारित हैं। वे होस्ट की अनुमतियों के पूरक हैं, विकल्प नहीं।
