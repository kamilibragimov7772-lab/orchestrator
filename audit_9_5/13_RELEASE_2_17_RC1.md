# Релиз 2.17.0-rc.1 — что доказано и что нет

**Статус: RELEASE CANDIDATE. Взвешенная оценка 9,285 из 10. Цель 9,5 НЕ достигнута
и не заявляется.** Два обязательных пункта не выполнены: семантический бенчмарк
семи ролей и независимое ревью кандидата. Пока их нет, любое «9,5» было бы
округлением вверх по осям, которые никто не мерил.

Кандидат: ветка `hardening/release-2.17-rc1`, PR #2. Базовый commit `1400491`.
Отчёты 00–11 остаются историческим срезом `8c7cbd8`; этот файл обновляет их.

## Что изменилось по существу

**R01 закрыт: у приёмки появилась граница, а не обещание.** Модель-приёмщик
работала с `Read, Glob, Grep, Edit` под `acceptEdits`, а «ничего не меняй, кроме
поля `priyomka` и секции `## Приёмка`» держалось фразой в промпте. Фраза не
граница дважды: она не мешает открыть соседний файл и не мешает **файлу отдать
приказ** — артефакт, который судят, читался тем же контекстом, который выносит
вердикт.

Конвейер: артефакты → детерминированные проверки → ограниченный пакет
доказательств → приёмщик **без инструментов** → JSON по схеме → **отчёт пишет
wrapper**. Замер до написания кода, Claude Code 2.1.263: приёмщик, запущенный с
`--tools "" --restricted --strict-mcp-config --setting-sources "" --permission-mode
manual`, отвечает `tools_available: []`, не читает файл, путь к которому ему дан,
и не изменяет его.

Детерминированный слой стал полом вердикта: понизить можно, поднять выше
проваленной проверки нельзя; `accepted` рядом с блокирующей находкой отклоняется
как самопротиворечие. Невалидный JSON, пустой ответ, таймаут и ошибка приёмщика
дают `failed` — не «пропущено».

**R03 закрыт.** CI зелёный на точном SHA кандидата: Windows/Linux/macOS ×
Python 3.10/3.12 плюс security. Защита `main` — ruleset с обязательными
проверками, запретом force-push и удаления. Что она работает, видно не из
настройки, а из поведения PR: при красном CI `mergeStateStatus` был `BLOCKED`,
после зелёного стал `CLEAN`.

**R04 закрыт в объявленном объёме:** Python 3.10 и macOS больше не «NOT TESTED» —
они в зелёной матрице. Медиа и site-build остаются вне сертифицируемой области.

## Что нашли прогоны, чего не видел прежний аудит

| Находка | Кто нашёл | Почему пряталось |
|---|---|---|
| Артефакт, объявленный как `../../../../etc/passwd`, читался и попадал в контекст модели | CI | На Windows такого файла нет — локально было зелено |
| `CLAUDE_CONFIG_DIR`, направленный на стек, уносил учётные данные CLI: `Not logged in` за 151 мс | живой E2E | Мок-тесты модель не запускают |
| Три из четырёх негативных сценариев показывали PASS, пока приёмщик вообще не стартовал | живой E2E | Отказ инфраструктуры неотличим от отказа по существу, если не различать их явно |
| Установщик выглядел неидемпотентным | шаг CI | Лишний файл оставлял `doctor` предыдущим шагом (`__pycache__`) |
| Невалидный скаляр frontmatter сообщался как `JSONDecodeError` | фикстура теста | Строгость верна, но автору нечего было чинить по такому сообщению |

Последние две — не дефекты продукта, а дефекты измерения. Они опаснее: красный
шаг по неверной причине глушат так же, как любую ложную тревогу.

## Методологическая опора

- Основной фреймворк: NIST SSDF 1.1 (NIST, 2022) — отбор рисков, проверка,
  доказательство, управление остаточным риском.

  инструментов агента и обращение с недоверенным контекстом; SLSA 1.2 (2025) как
  направление работы с происхождением поставки.
- Соответствие NIST или уровень SLSA **не заявляются**: это опора для отбора
  проверок, а не сертификат.
- Источники: [SSDF](https://csrc.nist.gov/projects/ssdf),
  [SP 800-218A](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-218A.pdf),
  [OWASP Agentic](https://genai.owasp.org/2025/12/09/owasp-top-10-for-agentic-applications-the-benchmark-for-agentic-security-in-the-age-of-autonomous-ai/),
  [SLSA 1.2](https://slsa.dev/spec/v1.2/),
  [Claude Code CLI](https://code.claude.com/docs/en/cli-reference).

  владельца, не стандарт NIST.
