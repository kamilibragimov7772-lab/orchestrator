# Оставшийся путь к 9,5

Hardening уже выполнен локально. Следующие этапы являются release gates; назначенные баллы не заменяют их результата. Оценки времени — плановые диапазоны, не факт трудозатрат.

| Этап | Результат / приёмка | Зависимости | Оценка |
|---|---|---|---|
| 1. Изолировать report-only reviewer | Модель не может изменить source/чужой файл; structured output применяет узкий writer | Решение о runtime границе | 0,5–1 день |
| 2. Независимая техническая и семантическая приёмка | Проверяющий видит бриф, diff и tests; P1 устранены, граница line-by-line coverage указана | Разрешённый /orchestr или reviewer wrapper по правилам владельца | 0,5–1,5 дня |
| 3. Реальный Claude E2E | Good-run принят, broken-run отклонён, reviewer failure виден; artifacts открыты | Авторизация CLI, синтетический vault | 0,5 дня |
| 4. Remote CI и защита main | Все matrix/security jobs зелёные на release SHA; broken PR блокируется | Публикация reviewable ветки и права GitHub | 0,5 дня |
| 5. Prompt/DX debt | Убраны обязательные отсутствующие ссылки, явно optional роли; проверены install profiles | Результаты E2E | 0,5–1 день |
| 6. Optional recipes | Зависимости закреплены либо scope сужен; один воспроизводимый render/build | Выбранные media/site inputs | 1–2 дня |
| 7. Повторный scorecard | Веса сохранены, каждый >=9,5 обоснован фактами, открытых P1 нет | Предыдущие gates | 0,25 дня |

Параллельно можно готовить dependency manifests и fixtures. Нельзя объявлять CI зелёным до выполнения workflow, independent review — до отдельного проверяющего, полное line-by-line — до покрытия всех файлов. 9,5 не требует полной паритетности Codex/Claude, но требует честно очерченной и проверенной поддерживаемой области.

## Внешние ограничения этой сессии

Правила владельца запрещают вызов субагентов без /orchestr или wrapper. Поэтому независимая приёмка не запускалась под другим именем или через CLI в обход правила. GitHub push/настройки main не делались. Готовая локальная ветка и этот пакет — конкретный предмет следующего разрешения и review.

## Методологическая опора

- Основной фреймворк: NIST SSDF 1.1, NIST, 2022 — риск, проверка, доказательство и управление остаточным риском.
- Дополнительная модель: SLSA 1.2, 2025 — направление контроля цепочки поставки; уровень SLSA не заявляется.
- Источники: [NIST SSDF](https://csrc.nist.gov/projects/ssdf), [SLSA 1.2](https://slsa.dev/spec/v1.2/), [Claude Code hooks](https://code.claude.com/docs/en/hooks).
- Дата проверки актуальности: 2026-09-06. Оценочная шкала и веса взяты из пользовательского аудиторского брифа; баллы — экспертная оценка, не стандарт NIST.
