# Валидация входа (канонический источник)

> **Обязательна для каждого агента стека.** Выполняется ПЕРВОЙ, до любой доменной работы.
> Введена 2026-08-21 по итогам аудита 40 определений: у 15 агентов входы были перечислены,
> но проверки их существования не было. Агент начинал работать по тому, что открылось,
> и выдавал валидный по форме артефакт на неполных данных.
>
> **Ужесточена и одновременно смягчена в тот же день** после ворот: первая редакция требовала
> конкретных полей `task.brief_path` и `output.expected_path` у всех сорока. Эти поля приходят
> не всегда — обёртки `/retro`, `/harness-audit`, `/openclaw-task` передают другую структуру,
> у части агентов в собственных примерах стоит `brief_path: null`, а `site-discoverer` по своей
> роли обязан работать как раз с сырым запросом. Правило, которое нельзя выполнить честно,
> не выполняется вообще — поэтому теперь проверяется **то, что нужно именно твоей задаче**.

## Правило

**Перечислить обязательные входы — не то же самое, что проверить их.**
Пока валидация не пройдена, доменная работа не начинается. Ни одной строки артефакта.

## Что проверять

Не фиксированный список полей, а **то, без чего именно твой метод не может дать честный
результат**. Для большинства агентов это три класса:

1. **Предмет работы.** Файл, каталог, URL, текст или данные, которые ты обязан разобрать.
   Проверка — фактическая: `Read` вернул содержимое, `ls` показал каталог, URL ответил.
   Упоминание пути во входе не равно существованию файла.
2. **Место для результата.** Каталог, куда ляжет артефакт, существует и доступен на запись.
3. **Опора, названная в твоём методе.** Брендбук, канон критериев, корпус текстов, ТЗ,
   учебник предметной области — если метод на них ссылается, они должны открыться.

Если структурированный INPUT от оркестратора пришёл — сверяйся с ним. Если агента дёрнули
slash-обёрткой или напрямую и структуры нет, это **не повод пропустить проверку**: проверяй
те же три класса по факту задачи.

## Что делать при промахе

**Обязательное отсутствует → стоп.** Возврат:

```yaml
status: error
escalations:
  - to: orchestr
    type: missing_input
    detail: "<что именно · как проверял · что получил>"
    recovery_hint: "<что положить и куда, чтобы прогон поехал>"
```

Работу **не начинать**. Частичный артефакт на неполных данных хуже отсутствия артефакта:
он выглядит готовым, и его принимают.

**Опциональное отсутствует → не стоп, а пометка.** Запиши в артефакт явно, чего не было
и как это сузило вывод: `[не проверено: нет доступа к X]`. Молчаливое сужение запрещено.

**Нечем выполнить обязательный шаг — тоже промах входа.** Метод предписывает действие,
для которого у тебя нет инструмента (нет `Bash` для расчёта, нет браузера для клавиатурного
прохода, нет `Write` для файла) — эскалируй `type: tool_unavailable`, не имитируй.
Правдоподобный отчёт о непроведённой проверке — худший из возможных выходов.

## Исключение: агенты, чья работа — достать недостающее

`brief-architect`, `site-discoverer` и другие агенты фазы 0 существуют ровно затем, чтобы
превратить сырой запрос в структуру. Для них сырой вход — не ошибка, а задача.
Их валидация сводится к двум пунктам: запрос передан и непуст; целевой каталог для артефакта
существует. Возвращать `missing_input` на неполноту предмета им **запрещено** — это отказ
от собственной роли.

## Формат в карточке агента

```markdown
## Валидация входа

| Что проверяю | Обязательно | Чем | Нет → |
|---|---|---|---|
| <предмет работы твоей задачи> | да | Read / ls / curl | error + missing_input |
| <каталог для артефакта> | да | ls | error + missing_input |
| <опора: брендбук, канон, корпус> | по месту | Read | обязательная → error; опциональная → пометка |
```

## Чего валидация не делает

- Не заменяет доменную проверку качества входа (полнота ТЗ, внутренние противоречия) — это Шаг 1.
- Не оправдывает отказ при опциональных пробелах: опциональное отсутствие → работаем с пометкой.
- Не выполняется молча: и прохождение, и провал фиксируются в возврате оркестратору.
