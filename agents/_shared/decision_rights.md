> Принцип: агент решает максимум локальных вопросов сам, **не возвращая в чат лишнего**, и эскалирует только тогда, когда без человека/orchestr нельзя.
> Эскалация в orchestr ≠ эскалация пользователю. Orchestr может разрулить много вопросов сам (бюджет, очерёдность волн, выбор агента).

## Три уровня решений

- **Сам** — решает агент, не спрашивая ни orchestr, ни пользователя.
- **→ Orchestr** — возвращает в `summary` блок «нужно решение orchestr» (бюджет, scope, добор данных).
- **→ Пользователь** — orchestr дальше задаёт вопрос пользователю; агент сам пользователю не пишет.

## Где живёт право принимать финальное решение

- **Бюджет ресёрча / scope** — orchestr (на фоне CLAUDE.md дефолтов).
- **Go / no-go по бизнес-вопросу** — пользователь.
- **Какой brandbook применить** — orchestr (по project-маркеру), если конфликт — пользователь.
- **Что попадает в financial / legal** — пользователь, всегда.
- **Структура vault и индексы** — knowledge-curator (это его экспертиза).
- **Инфра: правка hooks/env/прокси** — infra-engineer; ротация токенов и sudo — пользователь.

## Что агент не делает никогда

- Не звонит другому агенту напрямую (всё через orchestr).
- Не возвращает тело артефакта в чат (только path + summary).
- Не делает «заодно» — out-of-scope правки.
- Не выдумывает источники, фреймворк, данные.
- Не маскирует противоречия — фиксирует их явно.
- Не отвечает пользователю напрямую от своего лица; orchestr — единственный говорящий.

## Эскалационные триггеры (быстрая шпаргалка для агентов)

```
ESCALATE_TO_ORCHESTR if:
  budget_exceeded
  | data_gap (>=1 critical)
  | conflict_unresolved
  | scope_creep_detected
  | missing_input (brandbook / corpus / sitemap / sources)

ESCALATE_TO_USER (через orchestr) if:
  go/no_go decision needed
  | breaking change risk
  | financial / legal exposure
  | sudo / token / 2FA / VPN
  | scope/deadline/budget conflict
```
