# Orchestrator — 検証可能な Claude Code 用オーケストレーション基盤

**[English](README.en.md) · [Русский](README.md) · [简体中文](README.zh-CN.md) · [Español](README.es.md) · [Português](README.pt-BR.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Deutsch](README.de.md) · [Français](README.fr.md) · [हिन्दी](README.hi.md) · [العربية](README.ar.md) · [Türkçe](README.tr.md)**

Claude Code のセッションをオーケストレーターに変えます。ブリーフからウェーブ計画を組み、
各ウェーブで専門サブエージェントを走らせ、各ウェーブの成果は必ずファイルとして着地し、
最後に独立したレビュアーが受け入れか差し戻しかを判定します。
エージェントカード 41 枚、共有コントラクト 10 本、スラッシュコマンド 10 個、任意スキル 4 個。

MIT ライセンス。作者: **[@kamil_ibrgmv](https://instagram.com/kamil_ibrgmv)**。プロトコル **2.16.0**。

> **最初にお読みください — 言語について。** オーケストレーションのプロトコル、エージェント
> カード、受け入れ基準は**ロシア語**で書かれています。ツール類・テスト・インストール手順・
> コードコメントは英語です。エージェントそのものが目的なら、読むのはロシア語の Markdown に
> なります。エージェント基盤を信頼できるものにする「配管」が目的なら、そこは言語に依存せず、
> このリポジトリが存在する理由そのものです。

## なぜ作ったか

Claude Code のサブエージェント集は不足していません。不足しているのは**検証できる**ものです。
多くは Markdown ファイルのフォルダにすぎません。フックが本当に発火した証拠はなく、
シークレット検出器が正しいバイト列を見ている証拠もなく、
あるチェックが黙って機能しなくなっても何も落ちません。

このリポジトリは逆のトレードオフを取ります。エージェント本体はごく普通で、
**周辺の配管こそが主眼**です。

| 多くのコレクション | このリポジトリ |
|---|---|
| エージェントの Markdown のみ | エージェント **＋** ガード・インストーラ・ドクター・受け入れゲート・同期 |
| テストなし | **97 個のテスト**。標準ライブラリのみ、API 呼び出しなし、ネットワークなし |
| 「これを settings.json に足して」 | 衝突プリフライト付きインストーラ。**ドクターがガードを実際に実行**し、ブロックすることを要求 |
| フックは動く前提 | 3 ペイロードのスモークテスト: 無害は通過、シークレットはブロック、危険コマンドはブロック |
| 「安全です、プロンプトを信じて」 | プロンプト本文をアクセス境界として扱わない — [SECURITY.md](SECURITY.md) 参照 |

スクリプトで確認できることはすべてスクリプトが確認します。
プロンプトの中にしか存在しないルールは、黙って守られなくなるルールだからです。

## クイックスタート

**Python 3.10 以上**と **Git** が必要です。API キー不要、ネットワーク不要、モデル呼び出しなし:

```sh
git clone https://github.com/kamilibragimov7772-lab/orchestrator
cd orchestrator
python tools/verify.py
```

エージェント契約リンター、準備度カウンタの自己テスト、テストスイート全体、
シークレットスキャンを実行します。チェックアウト外には一切触れません。

自分で選んだディレクトリへインストールします。インストーラは**まず計画を出し、決して上書きしません**:

```sh
python tools/install.py \
  --destination /absolute/path/stack \
  --vault /absolute/path/knowledge-base \
  --mode minimal
```

計画を確認したら `--apply` を付けて再実行します。既存ファイルがあり内容が異なる場合、
インストールは停止し、あなたのファイルを保持します。その後、結果を確認します:

```sh
python tools/doctor.py --root /absolute/path/stack --installed
```

`minimal` は調査と Markdown 成果物向けの 7 ロールを入れます。`full` はソフトウェア／
サイト構築／メディアのパイプラインと、その外部依存を追加します。Windows での注意点と
Claude Code を新しいディレクトリに向ける方法は [INSTALL.md](INSTALL.md) を参照してください。

## 収録内容

| レイヤ | 役割 | 検証の境界 |
|---|---|---|
| `_orchestr_protocol.md`, `agents/`, `commands/` | ルーティング、契約、完了の定義 | リンターは構造を確認。回答の品質には人間の受け入れが必要 |
| `tools/verify.py`, `tests/` | 再現可能な 1 コマンド。異常系も含む | Claude API なし、外部 MCP なし |
| `tools/guard.py` | PreToolUse での資格情報・破壊的コマンドの検出 | **ヒューリスティックな多層防御** — ホストの権限とサンドボックスは維持すること |
| `tools/install.py`, `tools/doctor.py` | 非破壊インストール、準備状況レポート | ドクターは認証もモデル品質もテストしない |
| `tools/acceptance-gate/` | 実行ログの決定論的チェックと、任意のレビュアーワーカー | モデルワーカーは**既定で無効**。実機 E2E は未認証 |
| `tools/sync_stack.py` | 厳密な許可リストに基づく Git ブリッジ | 任意。分岐したブランチを勝手にマージしない |
| `tools/export_session.py` | オプトインのトランスクリプト書き出し | **既定で無効**。マスキングはパターン一致であり、プライバシー保証ではない |

### 受け入れゲート

最も時間をかけて詰めた仕組みです。実行が閉じたあと、**別コンテキスト**——オーケストレーターの
思考過程を一切見ていない——が、ブリーフに照らして成果物を判定します。
まず決定論的スクリプトが走り、モデルはスクリプトで判定できない部分だけを見ます。

- `run_status` と `verdict` は別のフィールドです。`done` でない実行は
  *「受け入れ対象外」*を返し、偽の合格は返しません。
- `SKIP` は**「不完全」**になり、「受け入れ」には決してなりません。PDF は
  *署名のみ確認——ビューアで開くこと*、`.docx` は*構造は解析できた、目視の受け入れは別*
  と報告されます。
- 終了コードは区別されます: `0` 受け入れ · `1` 差し戻し · `3` 不完全 · `4` 対象外 · `2` エラー。

根拠は作者が 259 回の実行で測った数字です。バリデータに落とし込まれたルールは 76〜100%
守られ、同じルールをプロンプト文にしただけの場合は 0〜39% でした。

## 意図的にやらないこと

信頼とは、多くの場合「そのツールが黙ってやらないこと」の一覧です。

- **インストール時に、自動の書き出し・ミラーリング・Git push・cron・モデルプロセスは一切
  有効化しません。** すべてオプトインで、明示的な設定が必要です。
- **`robocopy /MIR` 相当のミラーリングはしません。** 転送元にないファイルを転送先から
  削除しうるため、削除しました。
- **上書きしません。** 衝突するファイルがあればインストールを止めます。設定とフックは
  置換ではなくマージされます。
- **黙って合格にしません。** 依存の欠如や未実行のチェックは `NOT CHECKED` または `SKIP` と
  報告されます。獲得していない合格は決して報告しません。
- **証明していない評点を主張しません。** 「9.5/10」は目標であり**未認証**です。
  未解決項目は平均で薄めず [`audit_9_5/`](audit_9_5/) に列挙してあります。

## 検証の状況

CI は Windows / Linux / macOS × Python 3.10 と 3.12 で動き、すべての PowerShell スクリプトを
解析し、**Git 履歴全体**を Gitleaks でスキャンします。
[`.github/workflows/ci.yml`](.github/workflows/ci.yml) を参照してください。

緑のバッジは証拠ではないので、限界も正直に書きます。

- テストはツールの挙動を対象とし、エージェントが書く内容の品質は対象外です。
- 実モデルによる E2E の受け入れはスイートに**含まれていません**。
- ガードはヒューリスティックです。ホストの権限を補完するもので、置き換えるものではありません。

## 方法論の裏づけ

エンジニアリングの基準は **NIST SSDF 1.1**（NIST, 2022）——欠陥を再現し、直し、
壊れたケースを拒否する回帰テストを追加する——と、ホストの公式ドキュメント
（[Claude Code hooks](https://code.claude.com/docs/en/hooks)）です。2026-09-06 に確認。
SSDF はリスクの選別に用いており、適合証明として掲げてはいません。
